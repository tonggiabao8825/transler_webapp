# Transler — Đặc tả sản phẩm và thiết kế hệ thống

Product Requirements Document (PRD) · Version 1.0 · 09/10/2026

Transler được định hướng là nền tảng AI Document Translation & Processing, hỗ trợ dịch tài liệu giữ nguyên định dạng, chỉnh sửa PDF, chuyển đổi định dạng hai chiều và xử lý nhiều loại tài liệu khác nhau.

Phạm vi đặc tả dưới đây tập trung vào nghiệp vụ, use case, sequence diagram, kiến trúc xử lý, API, dữ liệu và yêu cầu phi chức năng. Không bao gồm UI/UX.

## 1. Phạm vi chức năng

| Module               | Chức năng                                     | Mức ưu tiên |
| -------------------- | --------------------------------------------- | ----------- |
| PDF Translation      | Dịch PDF Basic / Advanced                     | P0          |
| PDF Editor           | Chỉnh sửa nội dung PDF, crop và dịch lại vùng | P0          |
| PDF Conversion       | PDF ↔ DOCX, PPTX, XLSX, ảnh và HTML           | P1          |
| Document Translation | Dịch DOCX, PPTX, XLSX, TXT, Markdown          | P1          |
| OCR                  | Nhận dạng PDF scan, ảnh và văn bản trong bảng | P1          |
| AI Translation       | LLM, glossary, context, custom instructions   | P0          |
| File Management      | Quản lý file, lịch sử, tải xuống, xóa         | P0          |
| Account & Billing    | Free, trả phí, quota, credits                 | P1          |
| Developer API        | Tích hợp dịch/chuyển đổi vào ứng dụng khác    | P2          |

Quy ước: P0 là các chức năng cần cho MVP, P1 là giai đoạn mở rộng, P2 là chức năng dài hạn.

## 2. Tác nhân hệ thống

- Guest: người dùng chưa đăng nhập, sử dụng chức năng miễn phí trong giới hạn.
- Registered User: quản lý tài liệu, lịch sử và tác vụ.
- Premium User: sử dụng hạn mức cao hơn, Advanced Translation và các chức năng nâng cao.
- Administrator: quản lý cấu hình, hạn mức, tác vụ và vận hành.
- External Services: Translation Providers, LLM Providers, Object Storage, OCR và Conversion Engines.

## 9. Đặc tả chức năng chi tiết

### 9.1. FR-01 — Import và quản lý tài liệu

| Thuộc tính | Đặc tả                                                          |
| ---------- | --------------------------------------------------------------- |
| Input      | File upload hoặc URL HTTPS                                      |
| Định dạng  | PDF, DOCX, PPTX, XLSX, TXT, MD, HTML, PNG, JPEG                 |
| Validation | MIME, magic bytes, kích thước, số trang, file hỏng, file mã hóa |
| Output     | `documentId`, metadata, trạng thái phân tích                    |
| Storage    | Lưu file gốc bất biến, phiên bản và file kết quả riêng biệt     |
| Security   | Chống SSRF khi nhập URL, giới hạn redirect, chặn địa chỉ nội bộ |

Các trạng thái tài liệu: `UPLOADING`, `VALIDATING`, `READY`, `UNSUPPORTED`, `FAILED`, `DELETED`.

Giới hạn 30 trang chỉ áp dụng cho tài liệu PDF ở gói Free Public. Những định dạng khác cần có hạn mức tương đương dựa trên dung lượng, số trang sau khi render hoặc số ký tự xử lý.

### 9.2. FR-02 — PDF Translation

Input contract

```
{
  "documentId": "doc_123",
  "sourceLanguage": "auto",
  "targetLanguage": "vi",
  "mode": "advanced",
  "translation": {
    "provider": "openai",
    "model": "configured-model-id",

    "customInstructions": "Preserve technical terms"
  },
  "output": {
    "format": "pdf",
    "layout": "preserve",
    "bilingual": false
  }
}
```

Processing contract

1. Phân tích file và xác định loại trang: native text, scanned, mixed.
2. Nhận dạng vùng văn bản, bảng, công thức, hình ảnh và annotation.
3. Sinh danh sách `TranslationUnit` có định danh ổn định.
4. Chọn translation provider theo chế độ.
5. Dịch và kiểm tra kết quả theo từng unit.
6. Dựng lại PDF, cố gắng giữ tọa độ và bố cục gốc.
7. Kiểm tra thiếu text, tràn vùng và font.
8. Tạo bản kết quả và lưu các cảnh báo.

Output contract: `jobId`, `documentId`, `artifactId`, `status`, `pageCount`, `warnings`, `qualityReport`.

### 9.4. FR-04 — PDF Editing

Hệ thống quản lý thao tác chỉnh sửa dưới dạng các operation có thể lưu và phát lại.

```
{

  "baseRevision": 3,
  "operations": [
```

Các operation chính gồm `REPLACE_TEXT`, `ADD_TEXT`, `DELETE_TEXT`, `MOVE_BLOCK`, `RESIZE_BLOCK`, `CROP_PAGE`, `ROTATE_PAGE`, `DELETE_PAGE`, `REORDER_PAGE`, `ADD_ANNOTATION`, `RETRANSLATE_REGION`.

Mọi thay đổi phải gắn với một revision. Không ghi đè file nguồn; hệ thống tạo PDF mới khi người dùng export hoặc yêu cầu tạo bản xem trước.

### 9.5. FR-05 — Conversion Engine

Cần có `Format Registry` ánh xạ cặp định dạng sang converter phù hợp.

Ví dụ:

```
pdf -> docx    : PDFToWordAdapter
docx -> pdf    : OfficeRendererAdapter
pdf -> png     : PDFRasterAdapter
png -> pdf     : ImageToPDFAdapter
pdf -> xlsx    : TableExtractionAdapter
xlsx -> pdf    : SpreadsheetRendererAdapter
```

Mỗi adapter phải khai báo:

- Source MIME và target MIME.
- Khả năng hỗ trợ batch.
- Tùy chọn chuyển đổi.
- Mức độ giữ layout và khả năng chỉnh sửa.
- Điều kiện đầu vào không hỗ trợ.
- Cơ chế timeout, retry và cleanup.

Không coi conversion thành công chỉ vì file đầu ra tồn tại. Phải xác thực file mở được, đúng định dạng và có nội dung hợp lệ.

## 12. REST API Specification

| Method | Endpoint                       | Chức năng                 |
| ------ | ------------------------------ | ------------------------- |
| POST   | `/v1/documents`                | Upload file               |
| POST   | `/v1/documents/import-url`     | Import URL                |
| GET    | `/v1/documents/{id}`           | Metadata tài liệu         |
| GET    | `/v1/documents/{id}/pages`     | Cấu trúc trang            |
| POST   | `/v1/translations`             | Tạo job dịch              |
| POST   | `/v1/translations/regions`     | Dịch vùng                 |
| POST   | `/v1/conversions`              | Tạo job convert           |
| POST   | `/v1/documents/{id}/revisions` | Lưu chỉnh sửa             |
| GET    | `/v1/documents/{id}/revisions` | Danh sách phiên bản       |
| POST   | `/v1/exports`                  | Xuất file                 |
| GET    | `/v1/jobs/{id}`                | Trạng thái và tiến độ     |
| POST   | `/v1/jobs/{id}/cancel`         | Hủy tác vụ                |
| GET    | `/v1/artifacts/{id}/download`  | Nhận URL tải xuống        |
| GET    | `/v1/providers`                | Danh sách engine khả dụng |
| GET    | `/v1/usage`                    | Hạn mức sử dụng           |

Các endpoint tạo job nên trả `202 Accepted` cùng `jobId`. Tải file nên dùng URL có thời hạn hoặc streaming có kiểm soát quyền truy cập.

## 14. Non-functional Requirements

| Nhóm            | Yêu cầu                                                   |
| --------------- | --------------------------------------------------------- |
| Performance     | Upload không chặn request lâu; xử lý tài liệu bất đồng bộ |
| Scalability     | Worker scale độc lập theo loại tác vụ                     |
| Reliability     | Retry có giới hạn, checkpoint, idempotency                |
| Security        | File validation, sandbox, SSRF protection, rate limit     |
| Privacy         | File riêng tư mặc định, mã hóa khi lưu và truyền          |
| Data Retention  | Có thời hạn lưu rõ ràng, hỗ trợ xóa theo yêu cầu          |
| Observability   | Metrics, tracing, logs, job diagnostics                   |
| Compatibility   | Hỗ trợ các phiên bản định dạng phổ biến                   |
| Accessibility   | API có lỗi và trạng thái rõ ràng cho mọi client           |
| Maintainability | Adapter-based, versioned API, test tự động                |

### Quality metrics cần đo

- Translation completeness: tỷ lệ đơn vị văn bản được dịch hoặc chủ động giữ nguyên.
- Terminology consistency: tỷ lệ thuật ngữ tuân thủ glossary.
- Layout overflow rate: tỷ lệ vùng có chữ tràn hoặc bị cắt.
- Conversion success rate: tỷ lệ file chuyển đổi hợp lệ.
- Job failure rate: tỷ lệ tác vụ thất bại.
- Processing time: thời gian theo số trang, định dạng và engine.
- Cost per job: chi phí OCR, LLM, CPU, storage và bandwidth.

Không nên cam kết giữ bố cục tuyệt đối hoặc thời gian dịch cố định trước khi benchmark với tài liệu thực tế.
